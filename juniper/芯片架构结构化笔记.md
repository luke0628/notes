## 1. EACHIP

### 架构要点
- **适用平台**：EACHIP 基于线卡
- **芯片定位**：Juniper 较早期的 PFE 芯片之一，用于线卡上的报文转发
- **架构特点**：使用 xqss/mqss（交叉队列调度器/消息队列调度子系统）进行队列管理

### 关键命令
```bash
# 队列统计
show cos halp ifd queue-stats <ifd>

# IFD 流信息
show jnh ifd <ifd-#> stream

# 异常信息（需采集3次，间隔30秒）
show jnh <pfe-#> exceptions terse
show jnh <pfe-#> exceptions rate
show jnh <pfe-#> exceptions hbc
show jnh <pfe-#> exceptions hbc policer

# 主机路径统计
show jnh host-path-stats
show jnh host error

# CMError 检测
show cmerror module brief

# PFE 统计
show pfe statistics traffic
show pfe statistics error

# MQSS/XQSS 统计
show mqss <#> stats all
show xqss <#> drop counters
show xqss <#> sched queue <1008-1015> local-stats
show xqss <#> sched counters
show mqss <#> dstat stats
show mqss <#> cell stats
show mqss <#> dstat usemeter

# TOE (Traffic Ordering Engine) 统计
show toe pfe <pfe-#> mqss <ASIC_INT> toe-inst 0 packet-stats
show toe pfe <pfe-#> mqss <ASIC_INT> toe-inst 0 globals
show toe wedge-stats-summary

# 主机回环检测
show host_loopback status-summary

# 微码变量和内存池
show jnh <pfe-#> ucode-vars

# 调度器和线程
show sched
show thread

# 防火墙过滤
show filter counters

# DDoS 相关
show ddos policer stats all
show ddos state
show ddos scfd asic-flows
show ddos scfd ukern-flows
show ddos scfd proto-states all
show ddos scfd global-info
show ddos asic global-rx-errors
show ddos asic punt-proto-maps

# TTP 和 PFE 统计
show ttp statistics
```

2. 重点关注 exception、drop counter、hbc（心跳）异常
3. 使用 `show cmerror module brief` 检测芯片错误
4. 使用 `show host_loopback` 检查主机回环路径状态

## 2. MQCHIP

### 架构要点
- **适用平台**：MQCHIP 基于线卡
- **芯片定位**：与 EACHIP 类似的 PFE 芯片，是 EACHIP 的后继演进
- **架构特点**：使用 `show mqchip` 命令族替代 EACHIP 的 mqss/xqss 命令，输出流 stream 1151 相关统计

### 关键命令
```bash
# 队列统计
show cos halp ifd queue-stats <ifd>

# IFD 流信息
show jnh ifd <ifd-#> stream

# 异常信息（3次，间隔30秒）
show jnh <pfe-#> exceptions terse
show jnh <pfe-#> exceptions rate
show jnh <pfe-#> exceptions hbc
show jnh <pfe-#> exceptions hbc policer

# 主机路径统计
show jnh host-path-stats
show jnh host error
show cmerror module brief
show pfe statistics traffic
show pfe statistics error

# MQCHIP 专用统计（与 EACHIP 的区别点）
show mqchip <mqchip-#> counters all
show mqchip <mqchip-#> counters output stream 1151
show mqchip <mqchip-#> counters output stream 1151 queue <0-7>
show mqchip <mqchip-#> counters input stream 1151
show mqchip <mqchip-#> dstat stat 0 0
show mqchip <mqchip-#> dstat stat 0 <1016-1023>

# TOE 统计
show toe pfe <pfe-#> mq <ASIC_INT> toe-inst 0 packet-stats
show toe pfe <pfe-#> mq <ASIC_INT> toe-inst 0 globals
show toe wedge-stats-summary

# 其他（与 EACHIP 共通的命令族）
show host_loopback status-summary
show jnh <pfe-#> ucode-vars
show sched, show thread, show filter counters
show ddos * （DDoS 全套命令）
show ttp statistics
show pfe statistics notification / nhdb / discard
show packet / icmp / ipv4 statistics
show nhdb management resolve / operations / ipc
show nhdb mcast resolve
show nhdb type hold
show syslog messages
show nvram
```

### 调试方法
1. 支持完整的 DDoS SCFD（Software Control Flow Detect）检测
2. 使用 mqchip 特有命令检查输入/输出流 queue 0-7
3. TOE 命令使用 `mq` 关键字（EACHIP 使用 `mqss`）

## 3. XMCHIP

### 架构要点
- **适用平台**：XMCHIP 基于线卡
- **芯片定位**：与 EACHIP/MQCHIP 同代或稍新的 PFE 芯片
- **架构特点**：
  - 使用 `show xmchip` 命令族
  - 引入 phy-stream（物理流）概念
  - 使用 q-node（队列节点）统计替代部分 mqss 功能

### 关键命令
```bash
# 队列统计
show cos halp ifd queue-stats <ifd>
show jnh ifd <ifd-#> stream

# 异常信息
show jnh <pfe-#> exceptions terse / rate / hbc / hbc policer

# 主机路径
show jnh host-path-stats
show jnh host error
show cmerror module brief
show pfe statistics traffic / error

# XMCHIP 专用统计
show xmchip <xmchip-#> stats all
show xmchip <xmchip-#> phy-stream stats 1151 1
show xmchip <xmchip-#> phy-stream q-node-stats 1151 <0-7>
show xmchip <xmchip-#> phy-stream stats 1151 0
show xmchip <xmchip-#> dstat stats
show xmchip <xmchip-#> q-node stats 0 <1008-1015>
show xmchip <xmchip-#> dstat stat

# TOE
show toe pfe <pfe-#> xm <ASIC_INT> toe-inst 0 packet-stats
show toe pfe <pfe-#> xm <ASIC_INT> toe-inst 0 globals
show toe wedge-stats-summary

# 其他共通命令
show host_loopback * / show jnh ucode-vars, pool
show sched, thread, filter counters, ddos *
show ttp, pfe statistics *, packet statistics, icmp, ipv4
show nhdb *, syslog, nvram
```

### 调试方法
1. 重点关注 phy-stream 统计，stream 1151 是关键的 host path 流
2. q-node-stats 检查队列节点 0-7 的状态
3. 使用 `show xmchip dstat` 查看去往 CPU 的控制面报文统计

## 4. ZTCHIP

### 架构要点
- **适用平台**：ZTCHIP 基于线卡
- **芯片定位**：较新的 PFE 芯片架构，命令体系与前三者有显著差异
- **架构特点**：
  - 使用全新的 `show host-path` 命令族替代传统的 `show jnh` 命令
  - 引入更细粒度的网络协议统计分类（inet/inet6/layer2/proto/tag/tcp/udp）
  - 支持应用层统计（wedge-detect/icmp/icmp6/mlp/ppm/resolve/rpc/twamp/vxlanpkt）
  - 使用 `show sandbox` 进行令牌调试
  - 引入 `show cda xqss statistics server api` 命令

5. 应用层命令可直接定位 wedge、VXLAN、TWAMP 等高级功能问题

## 5. ICHIP

### 架构要点
- **适用平台**：ICHIP 基于线卡（MX 系列路由器广泛使用）
- **芯片定位**：Juniper I-chip PFE，经典芯片架构
- **架构特点**：
  - 使用 `show ichip`、`show ia`、`show npez` 等独特命令族
  - 支持 JSIM 仿真（详见第6节）
  - SID（Service ID）≥64 时转发到 Fabric
  - SID 到 FPC/PFE 号的转换公式因平台而异

### 关键命令

### ICHIP JSIM 仿真（来自 "JSIM (ICHIP).txt"）

JSIM 是 ICHIP PFE 的查找仿真工具，用于模拟报文查找过程。

#### 基本命令
```bash
# 重置仿真状态
jsim reset [full <jtree_instance>]

# 执行完整查找（含隐式重置）
jsim lookup [verbose, on-chip]

# 单步执行
jsim step [<count>] [verbose, on-chip]

# 显示当前状态
jsim
```

#### 设置命令
```bash
set jsim protocol ip|inet6|tag|<n>
set jsim pktlen <bytes>
set jsim iif <ifl>
set jsim sample <bits[3:0]>
set jsim ttl-expired <bit>
set jsim tcp <bit>
set jsim ip-options <bit>
set jsim ipdst <ipaddr>
set jsim ipsrc <ipaddr>
set jsim ip6dst <ip6addr>
set jsim ip6src <ip6addr>
set jsim ip-protocol <n>
set jsim src-port <n>
set jsim dst-port <n>
set jsim mpls-tag <bits[31:0]> [index <0-4>]
set jsim mpls-tag label-only <n> [index <0-4>]
set jsim fabric-token <n>
set jsim key-buffer <byte_offset> byte|short|word <value> [mask <mask>]
set jsim policer-result in-spec|out-of-spec|grace-pass|grace-fail|undef [index <index>]
```

#### 显示命令
```bash
show jsim keyb [raw]    # 显示 key buffer 内容
show jsim result        # 显示 result buffer 内容
show jsim policer-result
```

#### 典型示例
**IPv4 转发到 Fabric：**
```bash
jsim reset full 0
set jsim ipsrc 1.1.1.1
set jsim ipdst 14.0.0.2
set jsim protocol ip
set jsim iif 114
jsim lookup
```

**IPv4 转 WAN（从 Fabric 侧）：**
```bash
jsim reset full 0
set jsim input-port fabric
set jsim fabric-token 0x627
jsim lookup
```

#### SID → FPC/PFE 转换公式
| 平台 | 公式 |
|------|------|
| MX 路由器 | DPC# = (SID - 64)/4, PFE# = SID % 4 |
| T-Series / M320 | FPC# = (SID - 64)/2, PFE# = SID % 2 |
| M120 | FEB = (SID - 64), PFE = 0 |

#### JSIM ARP 回复示例
```bash
jsim reset full x
set jsim iif <ifl>
set jsim protocol 3
set jsim key-buffer 16 word 0x<DMAC first 4 bytes>
set jsim key-buffer 20 short 0x<DMAC last 2 bytes>
set jsim key-buffer 22 word 0x<SMAC first 4 bytes>
set jsim key-buffer 26 short 0x<SMAC last 2 bytes>
set jsim key-buffer 28 short 0x0806
set jsim policer-result in-spec
```

## 6. PECHIP (Paradise)

### 架构要点
- **适用平台**：PECHIP 基于线卡（PTX 系列路由器）
- **芯片定位**：Paradise 芯片组，新一代高性能 PFE
- **架构特点**：
  - 完整的流水线架构：Port Group → Ingress Buffer → Ingress Packet Processor → VOQ Manager → Fabric Interface → Fabric Scheduler → Output Queue Manager → Egress Buffer → Egress Packet Processor
  - 引入 Lcpu（本地 CPU）和 eth2/eth_host/eth_jflow 网络接口
  - 使用 BCM shell（telnet 127.0.0.1:50009）
  - 支持 `debug expr-if trace` 命令族

## 7. TLCHIP/TQCHIP (Broadway)

### 架构要点
- **适用平台**：TLCHIP/TQCHIP 基于线卡
- **芯片定位**：Broadway 芯片组，TLCHIP 处理入口/出口查找，TQCHIP 处理流量管理/排队
- **架构特点**：
  - TLCHIP 和 TQCHIP 成对工作（通过 `show jspec client` 验证）
  - TLCHIP 包含 SLU（Source Lookup Unit）和 DLU（Destination Lookup Unit）
  - TQCHIP 处理 CM（Congestion Manager）和 Fabric 接口
  - 每个 FPC 可以有多个 TLCHIP/TQCHIP 实例

### TLCHIP JSIM 仿真

#### JSIM 参数设置

### 8.4 Enhanced-IP 不一致检测

当配置了 `network-services enhanced-ip` 但各组件状态不一致时，按以下步骤排查：

```bash
# 1. 检查两个 RE 的 CLI 配置
show chassis network-services

# 2. 检查 BSD shell 内核配置
sysctl net.netsvc
# net.netsvc: 2  → enhanced-ip

# 3. 检查 PFE 组播状态
show jnh 0 vc mc state
# VC Mode Active: NO → TRINITY-ONLY → enhanced-ip
# Enhanced IP: Enabled

# 4. 检查 NHDB 硬件组播
show nhdb hw mcast
```

**状态解读：**
- `net.netsvc: 2` → Enhanced-IP 模式
- `VC Mode: TRINITY-ONLY` → Enhanced-IP
- `VC Mode: ICHIP INTEROP` → 传统 IP 模式

**相关 PR：**
- PR 1282499 - RE 成为 Master 后未启用 enhanced-ip 内核模式
- PR 1336378 - PTX/MX 增强模式在 MASTER/BACKUP RE 间不一致
- PR 1149928 - Enhanced-IP 未传播到线卡导致 ARP 请求 SW error 丢弃
- PR 1273832 - Enhanced-IP 下组播流量入站 SW error 丢弃
- PR 1357110 - 增强 `show chassis network-service` 显示内核和 FPC 级别详情

### 关键演进趋势

1. **命令体系统一化**：早期芯片（EA/MQ/XM）使用 `show mqss/xqss/mqchip/xmchip` 等；ZTCHIP 采用全新 `show host-path` 命令族；PECHIP/TLCHIP 使用 `show pechip/tlchip/tqchip`。
2. **仿真能力增强**：ICHIP 引入 JSIM，PECHIP 和 TLCHIP 进一步完善。
3. **主机路径可视化**：从隐式的 `host_loopback` 演进到显式的 `show host-path` 和 `debug expr-if` / `debug bwy-if`。
4. **Trapcode 调试标准化**：PECHIP 和 TLCHIP 统一了 trapcode dump 流程，`set jsample` + `debug ... trace host clog` 成为标准操作。
